# NTRU 混合求解对照：阶段 1 证据核查

本轮依据用户分阶段要求，仅核查代码、配置、环境与既有结果，建立证据清单。没有生成新密钥，没有启动求解、约化、筛法、独立 evaluate 或参数扫描，也没有重跑测试。阶段 2 尚未开始。

核查结论：当前代数和共享 BKZ／Slicer 接口可以复用，q=97 的 A/B 结果证据完整；新的 B/D/E 公平对照还需要补齐候选策略、方法模式、约化口径、统计和强进程树限时。现有数据尚未证明 q=97 完整方法或 Slicer 的净收益。

- 使用当前本地目录；分支 `experiments/ntru-e2e-phase1`，HEAD `452be18c741a2d81c106d3bfe3847428ed57229b`。`experiments/` 和 `main.pdf` 为未跟踪内容，所以仅凭 HEAD 不足以标识实验实现，另保存 83 个现有源码／配置／说明文件的 SHA-256。
- 当前 remote 为 `git@github.com:endofinca-svg/hybrid-primal-ntru.git`，名称与用户总说明中的 URL 不同。未修改 remote，也未把远程版本当作当前工作区。详见 [workspace.json](workspace.json)。
- 当前 q=97 公钥文件符合预期：n=128、固定三元总重量 `(12,24)`、独立随机正负号、不强制平衡，秘密平方范数为 36。密钥生成仅因 f 不可逆而拒绝。详见 [model.json](model.json) 及 [生成代码](../../ntru_e2e/generate.py:22)。
- 商环为 `F_97[x]/(x^128+1)`；公开关系为 `h*f=g`，列作用矩阵满足 `A*f-g=0`。pattern 约束 f 的 P 坐标为零；P/C/T 构成不交分划。
- 实际行基为 `[[qI,0],[A_C^T,I]]`，坐标顺序 `(g,f_C)`，维数 `d=2n-k-κ`；κ=0 时为 `d_pat=2n-k`。
- 目标 `t(u)=(-A_T*u,0)`；使用实际目标表示从 `v-t` 重构，再填入 `f_T=u`、`f_P=0`。旋转必须为共同带符号负循环旋转，不能用普通数组循环移位替代。

上述结论来自本地 public/config 和当前代数源码，不是由项目总说明直接假定。阶段 1 未读取 private 真值文件。

解释限制：

1. A 原先没有超时上限，473.11 秒只是实测用时取整；B 每 pattern 上限 473.11 秒、每组上限 473.11×k。因此已有 A/B 不是相同预算下的成功率比较。
2. 十个 k 共用一个公钥，不能解释为十个独立实例。k=40 是该公钥已测网格上的事后最优点；β/tours 尚未分别合理优化，新 k=36 也未测。
3. A/B 的首次 β 来自从 30 开始、步长 1、未成功时每 β 严格两轮的连续轨迹。k=40 在 β=32 第 2 轮成功，不等于冷启动 β=32 两轮的实测结果，也不是最小可成功 β 的证明。
4. 34 次超时是删失观测，不等于 34 次已证 pattern 不兼容。A/B 都是 κ=0 的非零基行流程，target 与 Slicer 调用均为 0。
5. 原有最多八轮 A 与已删除的旧 pattern 批次不并入本次费用或结论。

## 4. 阶段 2 必须补齐的事项

1. **候选规则与统一统计。** 当前只支持完整非零枚举、再全局字典序排序，没有 HW 上限参数。新 `1≤HW(u)≤2/3` 生成器须直接按支持重量生成，避免 κ=12 时先生成 531440 项再截断。冻结候选序、ID、seed，分开保存原始空间、规则保留、精确目标去重、内部投影分组、实际提交／完成／未覆盖的数目和 ID。
2. **提交与完成分开。** 当前 `processed_guess_ids` 在 Slicer call 开始时更新，只能证明提交；内核饱和依据残差条数，允许 0 次迭代返回，也不保证逐 target 全部解码成功。Babai 中断时也缺少“已尝试但无候选”的逐目标进度。输入同序不等于 Slicer 内部处理同序，需要单独记录内部合并、排序及其对首命中比较的影响。
3. **固定基模式和端到端模式分开。** 当前 worker 串行跑全部 arms，即使成功仍继续；派生的 setup+arm 时间不能冒充独立方法实际端到端时间。固定基实验要保存／核验同一个基；端到端实验需要独立方法选择、停止规则和预算，并给每种方法计入自身全部必要成本。
4. **统一或明确区分约化后端。** q=97 A/B 使用 MPFR 192 位、proved LLL、冻结 BKZ2 策略及显式严格 tour；旧混合 adapter 使用 long double、默认 LLL 和 `MAX_LOOPS` 上限。两者目前不是同一约化协议。D/E、C/F 必须严格同基；B 与 D/E 的总成本比较也须冻结公共数值／后端口径或明确分组优化，不能把这些差异误记为 Slicer 收益。记录实际 β、tours、投影维数及编译上限 64，不能把 max_loops 当成完成 tours。
5. **覆盖与成功分类。** 跳过零猜测必须记录覆盖损失；非零短向量行分支单独计费和标注。三个覆盖事件分开保存：pattern 兼容、兼容且有效非零尾部在列表中、实际解码重构。在线成功只依据公开关系和短向量约束；参考原样、共同带符号旋转等价、其他有效短向量仅在独立 evaluate 分类。现有旧汇总按参考等价确认成功的口径不能无标注地套到新定义。
6. **强进程树限时与内存。** 现有 TERM 后只等直属进程；若直属进程先退出而后代忽略 TERM，最终 KILL 分支不会触发，未形成强树清理保证。阶段 2 应补真实轻量进程树回收回归及清场检查／cgroup 方案。`RUSAGE_CHILDREN.ru_maxrss` 是捕获进程历史高水位；与 worker 自身 RSS、整个树的内存分开，强杀时缺失也如实标注。
7. **环境和收益归因。** 当前固定后端 commit、11 个源码和 2 个编译扩展与既有快照匹配，轻量 imports 成功。旧测试日志不能称本轮重测通过。新测试覆盖候选数、去重 ID、计费、停止规则、零目标、树限时和 Slicer/Babai 增量；不能仅凭出现 Slicer 路径候选就判有增益。

具体源码位置和逐项证据见 [CODE_REVIEW.md](CODE_REVIEW.md)、[BACKEND_REVIEW.md](BACKEND_REVIEW.md)。
