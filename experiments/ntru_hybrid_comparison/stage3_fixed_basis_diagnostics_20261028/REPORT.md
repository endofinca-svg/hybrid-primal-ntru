## Q1：为何第一次内核迭代前就停止？

准确源码位置、原逻辑与计数器定义见 [SOURCE_AUDIT.md](SOURCE_AUDIT.md)。

`e.len` 是归一化投影坐标的**平方和**，排序用 `cdb_t[].len` 的 float32 保存值。投影坐标由尾部 GSO 系数乘 `sqrt(r_i/gh_sub)` 得到，`gh_sub` 是平方尺度。阈值为全部成员公开环境残差平方半径的最小值除以 `gh_sub`，再乘 `1.0001`。

index 2 实测：

```text
gh_sub                     = 5.748818646657477
min public ambient bound²  = 32
threshold                  = 32 * 1.0001 / gh_sub
                           = 5.566917651613093
target entries N           = 640
signed projection groups Nt= 40
scalar                     = (40 + 0.5) / 40 = 1.0125
index = floor(Nt * scalar) = 40（从零计数，即第 41 小条目）
cdb_t[40].len              = 2.1942403316497803
comparison                 = 2.1942403316497803 < 5.566917651613093
```

判断发生在循环体**之前**，严格小于成立即返回。规则只保证640 个条目中至少 41 个满足这个略放松的投影平方界，不检查每个投影组或原始目标。实际本轮有 638/640 条目低于界，覆盖全部 40 组；这是实测额外事实，不能升级为该规则本身的保证。

它不保证 212 维完整残差的半径，更不保证 256 个 f/g 系数满足公开条件。原 `force_kernel_iterations` 的实际数值作用是把此阈值置零，但配置要求 interface test 模式；它自身不会自动换数据库。本轮没有使用该开关，独立 probe 仅显式绕过原饱和判断并改变迭代上限，其余流程保留。

## Q2：投影已停止时，完整结果怎样？

D-normal 正常调用一次，entered/completed/legacy 迭代、替换、成功约化均为 0，退出为 `projection_saturation`。1280 次提升全部落在返回半径之外。最小环境残差平方为 **300015**，该条目尾部平方贡献 3，完整范数平方为 **300018**，远大于公开目标 36。

完整范数始终按 `||g||² + ||f_C||² + ||f_T||² + ||f_P||²` 恢复，其中 f_P=0，所以 `完整范数²=212维残差²+猜测尾部²`。投影维数 40、环境维数 212 和完整 f/g 共 256 项的范数没有混用。

已知正确尾部 ID21/22 的最佳完整范数也分别为 1775351，未过半径。正确尾部已覆盖不意味着当前约化基和提升流程能恢复其 witness。

## Q3／Q4：随机化与内核迭代分别改善了什么？

四个 index 2 D 配置从独立重建状态开始；所有 11 个比较的可观测字段一致，包括整数基、有序／无序格 DB 与目标 DB、两份可取得 RNG 状态、LSH seed、GSO 尺度、目标顺序及 ID 映射。前态额外提升在独立 GSO 上进行，结束后原状态摘要完全不变。

- **E 与 D-skip：** D-skip 相对自身未随机化条目，在 22/80 个目标上改善最佳完整范数，但在 80/80 个目标上仍劣于直接 E。原始条目加 15 个随机化条目及额外提升没有带来公开收益，不能归给内核。
- **D-skip 与 D-normal：** 全部 1280 条后态的身份、投影、整数向量、系数、残差及重构结果完全相同。此处正常调用的零迭代没有增量效果。
- **单步 probe：** 568 次替换生成 568 个新条目，全部相对来源祖先的投影平方长度下降。对应 1136 条正负成员提升中，完整范数 672 条下降、464 条上升。按目标最佳值与 D-skip 比，34 改善、34 相同、12 变差；全局最小完整范数仍为 300018。
- **400 次 probe：** 投影第 41 小值降为 1.0188934803009033，最大值降为 1.3065664768218994，640 个条目全部低于原停止界。632 个最终新条目对应 1264 条成员提升，其投影均改善，完整范数 1064 条下降、200 条上升。按目标最佳值与 D-skip 比，60 改善、16 变差、4 相同。全局最小完整范数改善为 289218，但 80/80 个目标仍劣于 E，没有半径或公开验证成功。

400 次探针的最佳完整结果来自 **ID69、尾部[-1,1,-1,1]、group37、slot73、UID10617238931331083247**，是内核改变后的随机化来源条目：环境残差 289214，加尾部 4 得 289218。最小投影值仍为 0.7780178785324097，属于另一个未改变原始条目 ID50，其完整范数为 300018。不能把两个条目的最小值拼成一次改善。

已知 ID21/22 的完整最佳值序列为：E 56625；D-skip／normal 1775351；probe-1 1318327；probe-400 679797。可看到内核增量改善，但完整正确结果仍未出现。

这些比较满足已记录的可观测前态配对。UID 哈希桶布局、simhash 表本体和线程池内部状态没有完整序列化；因此不作超出可观测状态的无条件因果保证，也不由单次结果推断总体成功概率或统计加速比。

## 实现解释、祖先追踪与仍待验证的修复

**提升坐标问题。** 当前 `_lift` 调用 `G.to_canonical(coordinates,start=172)`。所固定 fplll 的实现只对该子基区间求系数并乘原始尾部基行，返回的是子基代表；它省略了消除全局前缀 GSO 分量所需的前缀系数。直接把它作为全局正交尾部残差从 target 中减去，会扰动头部提升。80/80 个目标中，E、D 未随机化条目和投影准备的最后 40 个整数系数完全相同，但 E 与 D 的前 172 个系数都发生变化。ID0 的完整范数从 E 的 58934 变为 D 原始条目的 2024789。

这是源码解释与整数证据共同支持的实现问题，**修正后的实际恢复效果尚未测试**。生成向量仍是整数格向量，完整范数和公开验证结果仍有意义；不能据此把本轮失败改写为修复成功。推导、安装头文件摘要、固定版本实现出处和二维精确例子在 [LIFT_FINDING.md](read_only_checks/LIFT_FINDING.md)。

**400 次祖先字段校正。** UID 会重用，原简化 `ancestor_uid` 的“最后一个 parent”字典在 2 个最终条目、4 条成员提升上给错祖先。原始创建／替换事件完整保留，按时间和槽位重放 12490 个事件后无重放错误，已恢复正确祖先。上述 400 次配对统计使用校正结果；原始遥测未改写。见 [chronological_ancestry.json](read_only_checks/p2_D-probe-400_chronological_ancestry.json)。
